# Business Email: Google Workspace + Cloudflare

Last prepared: 2026-07-31.

Status: paid future option, not the current PawJai setup. For the free setup that is active now, see `docs/playbooks/free-business-email-cloudflare-routing.md`.

This playbook sets up human PawJai inboxes at `@pawjaipet.com` while keeping Resend for app-generated transactional email.

## Mental Model

- Cloudflare keeps owning DNS for `pawjaipet.com`.
- Vercel keeps hosting `www.pawjaipet.com`.
- Google Workspace becomes the mailbox provider for human inboxes such as `firstname.l@pawjaipet.com`.
- Resend stays the app email provider for booking, ad, donation, verification, and notification emails.
- Google Workspace and personal Gmail are separate accounts. Employees can use the Gmail interface, but their login is a company identity such as `name@pawjaipet.com`, not `name@gmail.com`.

## Historical DNS Baseline

Before Cloudflare Email Routing was activated on 2026-07-31, public DNS answered:

```txt
NS pawjaipet.com = april.ns.cloudflare.com, brady.ns.cloudflare.com
MX pawjaipet.com = none found
TXT pawjaipet.com = none found
TXT _dmarc.pawjaipet.com = none found
```

That meant business inbox receiving had not been configured yet. The current free setup uses Cloudflare Email Routing; see `docs/playbooks/free-business-email-cloudflare-routing.md`.

## Recommended Address Pattern

Use paid Google Workspace users for people who need their own login, calendar, Drive ownership, and private mailbox:

```txt
firstname.l@pawjaipet.com
```

Examples:

```txt
sudlabha.s@pawjaipet.com
employee.n@pawjaipet.com
```

Use aliases or Google Groups for roles/shared identities:

```txt
hello@pawjaipet.com
adoptions@pawjaipet.com
support@pawjaipet.com
donations@pawjaipet.com
partners@pawjaipet.com
press@pawjaipet.com
security@pawjaipet.com
```

Avoid using `admin@pawjaipet.com` as a daily human login. It attracts account attacks and makes audit trails unclear. If needed, make it a group or alias that forwards to named humans.

## Setup Order

1. Sign up for Google Workspace with `pawjaipet.com`.
2. Create the first Super Admin user.
3. Add all initial human users before changing MX records.
4. Add Google domain-verification DNS record in Cloudflare.
5. Add Google Gmail MX record in Cloudflare.
6. Add SPF in Cloudflare.
7. Activate Gmail in Google Admin.
8. Generate DKIM in Google Admin, then add the DKIM TXT record in Cloudflare.
9. Add DMARC after SPF/DKIM have propagated.
10. Configure Resend on a sending subdomain, then update the app sender only after Resend verifies.

## Cloudflare Records

Google's current official Workspace MX setup uses a single MX target. If the Google Admin Console shows different values during setup, copy Google's console values exactly.

### Gmail Receiving

```txt
Type: MX
Name: @
Mail server: smtp.google.com
Priority: 1
TTL: Auto
Proxy: DNS only
```

Remove any other root `MX` records before activating Gmail. Multiple old MX providers can make inbound mail unreliable.

### SPF

If only Google Workspace sends from the root domain:

```txt
Type: TXT
Name: @
Content: v=spf1 include:_spf.google.com ~all
TTL: Auto
```

If another sender must send from `@pawjaipet.com`, merge it into the same SPF record. Do not create multiple root SPF TXT records.

### Google DKIM

Google Admin generates this value after Gmail is active. Add exactly what Google gives:

```txt
Type: TXT
Name: google._domainkey
Content: <value generated by Google Admin>
TTL: Auto
```

Google may require 24-72 hours after Gmail activation before it can generate the DKIM key.

### DMARC

Start in monitoring mode:

```txt
Type: TXT
Name: _dmarc
Content: v=DMARC1; p=none; rua=mailto:dmarc@pawjaipet.com
TTL: Auto
```

Create `dmarc@pawjaipet.com` first as a group or alias. After reports look clean, move gradually to `p=quarantine`, then `p=reject`.

## Resend Split

Do not use Resend as the root-domain mailbox provider. Google should own the root `MX` records for `pawjaipet.com`.

For app email, verify a Resend sending subdomain such as:

```txt
mail.pawjaipet.com
```

Then use app senders like:

```txt
PawJai <no-reply@mail.pawjaipet.com>
PawJai <notifications@mail.pawjaipet.com>
```

Use a human reply destination such as:

```txt
hello@pawjaipet.com
```

Only update `PAWJAI_EMAIL_FROM` in Vercel after Resend shows the sending domain as verified.

## Verification Commands

Run these after saving DNS records:

```sh
dig +short MX pawjaipet.com
dig +short TXT pawjaipet.com
dig +short TXT google._domainkey.pawjaipet.com
dig +short TXT _dmarc.pawjaipet.com
```

Expected early result:

```txt
MX includes smtp.google.com
TXT includes v=spf1 include:_spf.google.com ~all
TXT _dmarc includes v=DMARC1; p=none
```

DKIM appears only after Google generates the key and the TXT record is added.
